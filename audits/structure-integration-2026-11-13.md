# Internal musical windows and common PCM playback — integration in progress

Baseline: PR #59, `b656c1573c3d71d023125c906864d7f0b643bbb8`.
Whole-recording source run: [43463500768](https://github.com/stefanovillaggio8-dot/music-box/actions/runs/43463500768).

The 16 source artifacts cover all 1,176 indexed originals without source-analysis errors: 68,323 accepted model/PCM bars on 1,168 tracks, 8,375 novelty boundaries on 1,149 tracks, 4,689 phrase hypotheses on 904 tracks. The original search produced 5,493 entry windows on 1,109 tracks and 102 early exit windows on only 63 tracks. Model posteriors, metrical phase hypotheses, and arrangement novelty are not human downbeat/phrase/semantic annotations. Verse, chorus, build and drop labels remain unknown.

The new compiler evaluates internal windows against the original PCM contour and local harmonic snapshots, with the existing >=90% one-to-one actual attack agreement, <=40ms RMS timing, and stricter 12-pulse route for different percussion patterns. It also checks meter, bar count, downbeat residual, separated vocal overlap, source identity, and complete coverage. Different bass-boost versions of the same file are excluded as a transition to the same recording.

The first search bottleneck was exit availability. The refined search includes instrumental groups after measured section changes, retaining explicit bar-span hypotheses. It also changes the outgoing envelope: the original vocal remains at full gain until a final 400ms fade, wholly inside a 650ms measured quiet lead and 350ms of original post-boundary context. Vocal energy thresholds are unchanged. It does not gain permission to fade a singer merely because a model estimated a phrase boundary. The pinned source model evidence is reused; every new window gets newly decoded SHA-verified PCM.

Common rendering combines both original recordings offline through SoundTouch, applies one measured peak bound, and stores a bounded stereo lossless FLAC plus source/cue/content hashes. The foreground player replaces the native signal with binary `muted` during that verified buffer, leaving Safari's unreliable native volume control out of the attenuation path. Missing/stale assets or decoder/clock errors keep the native fallback. Pause, seek, visibility, room and queue changes cancel the common path. Native adoption starts muted before `play()` and becomes audible only after clock validation. This is not physical iPhone/background certification.

Initial common rendering: all 17 existing plans rendered at 48kHz, decoded back from FLAC with sample peaks <=0.960001. Chromium locally exercised decoding, native handoff and seek rollback; local Windows WebKit has no AudioContext implementation, so the Linux WebKit workflow must supply that evidence. General regression at this stage: 591/591. Full internal-window audit and final browser results are pending.

Karaoke: the original `onnx-community/whisper-tiny` export lacks cross-attention outputs and fails real word-timestamp extraction. The worker now selects the [timestamped export](https://huggingface.co/onnx-community/whisper-tiny_timestamped), keeping the multilingual model, fp32 encoder, q4 decoder and exact lyric/occurrence guards. The reproducible benchmark uses [JamendoLyrics manual word references](https://huggingface.co/datasets/jamendolyrics/jamendolyrics), never ASR-generated ground truth. Initial external English test: 34/468 reference words accepted, onset absolute median 46.14ms, p95 188.77ms; rejected words are not counted as accurate. This is poor coverage and does not prove Italian accuracy. An experimental English CTC comparison is not enabled in the player.

Model sources: [Beat This](https://github.com/CPJKU/beat_this), [Spleeter](https://github.com/deezer/spleeter). Model file SHA256 values are pinned in the analyzer. The Spleeter checkpoint manifest is required; without it TensorFlow Estimator can silently initialize a random network despite downloaded weight files.
